# 二叉搜索树：有序性是怎么被维护的

> Web 前端开发课程项目 · 个人项目 · 第 9—16 周
> 在线访问：https://echo33550336.gitee.io/web-frontend-bst/ （第 16 周上线）

三个难点，三种交互，串成一条学习路径：

| 页面 | 难点 | 交互类型 |
| --- | --- | --- |
| `src/d1.html` | 插入时的比较路径 | 参数探索型（拖滑块，路径与区间实时重算） |
| `src/d2.html` | 删除双孩子节点为何用中序后继替换 | 步进推演型（第 5 步内嵌一次操作判定） |
| `src/d3.html` | 插入顺序如何导致树退化 | 对照比较型（双画布同步插入 + 统计读数） |

## 怎么跑起来

不能直接双击打开（浏览器会拦截 `fetch` 读取 `data/*.json`）。在仓库根目录起一个静态服务器：

```bash
python -m http.server 8000
# 然后访问 http://localhost:8000/src/index.html
```

部署到 Gitee Pages 后直接访问 `src/index.html` 即可。

## 两条设计约束

1. **知识内容与代码分离**：所有讲解文字、步骤说明、参数定义都在 `data/*.json`。改文案只改 JSON，不碰 JS。
2. **三个难点的交互互相独立**：`d1.js` / `d2.js` / `d3.js` 各自负责一页，只共用 `common.js` 里的导航、播放控件与工具函数。
