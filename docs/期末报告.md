## 1. 项目概述

课程里二叉搜索树（BST）的插入、删除、退化三个知识点，教材通常用静态图 + 一段伪代码讲完。但初学者真正卡住的地方是：

- 插入时，比较一次为什么就能排除一半候选位置？
- 删除有两个孩子的节点时，为什么一定要用中序后继（或前驱）替换，直接拿一个孩子顶替会怎样？
- 同样的数据、不同的插入顺序，为什么树高会差出一倍？

本项目把这三个「为什么」做成三个可操作的网页：拖滑块看比较路径、单步推演删除、双画布对照插入顺序。三个页面共用一棵 SVG 树的纯函数模块，讲解文字全部放在 JSON 里。

## 2. 三个难点的设计

| 页面 | 难点 | 交互类型 | 核心交互 |
| --- | --- | --- | --- |
| `src/d1.html` | 插入时的比较路径 | 参数探索型 | 拖动待插入值滑块，实时重算比较路径、区间链与候选位置计数；可调树规模并随机重生成；播放完整插入过程 |
| `src/d2.html` | 删除双孩子节点 | 步进推演型 | 叶子 / 单孩子 / 双孩子三种情形；双孩子八步推演；第 5 步 A/B/C 判定（选错停在本步、演示断链与丢节点，可重试） |
| `src/d3.html` | 插入顺序与退化 | 对照比较型 | 同一批数，左树按「有序程度」扰动、右树升序，双画布同步逐步插入；树高 / 平均查找步数 / 最坏查找步数对比 + 折线；可重排换顺序 |

三个页面首页有统一入口和学习进度记录，页面顶部互相联通，构成一条「插入 → 删除 → 退化」的学习路径。

## 3. 实现与架构

- **纯函数内核 `src/js/tree.js`**：`buildTree / insertNode / removeNode / inorder / height / searchSteps / intervals / pathFor / countSlots / layout / render`。布局用「中序序号当 x、深度当 y」，不依赖 DOM，Node 里可直接测。
- **单向数据流**：页面状态（当前步、树快照）→ 渲染函数 → SVG，不在事件里手改 DOM 样式，因此前进/后退/重置都能确定性重画。
- **数据与代码分离**：三个难点的标题、步骤文案、参数、A/B/C 选项、结论模板、折线读数选项都在 `data/d1.json`、`data/d2.json`、`data/d3.json`；改文案不改 JS。
- **共用外壳 `src/js/common.js`**：JSON 加载、播放控件（播放/暂停/上一步/下一步/重置/速度）、学习进度（localStorage）。`src/css/style.css` 提供三页共享的版式与动画。
- **零运行时依赖、零构建**：原生 ES5 语法、SVG、`fetch`；`tools/serve.js` 是零依赖静态服务器。

## 5. 迭代与 AI 辅助

- 第 10—12 周：仓库骨架、数据分离、d1 树渲染与路径、三份 JSON 文案；d2/d3 从骨架提前做到完整交互。
- 第 13—14 周：d2 的 A/B/C 判定与摘挂动画、d3 双画布与统计、迭代报告与性能对比。
- 第 15—16 周：折线读数切换、页面导航与学习路径、`tools/serve.js`、演示脚本、期末报告与最终回归。
- 第 4 轮核对：用真实 headless Edge 截图（1440/1024/680）与 Lighthouse 验收四个页面，按审计修 favicon/`main`/标题层级/CLS；d1 重复值与边高亮、d2 直接孩子文案与 A/B/C 唯一性、d3 按步紧凑布局与折线轴标签一并修复；新增 `tools/bench.js`。
- AI 辅助记录见 `docs/iteration-1.md` 与 `docs/iteration-2.md` 的「AI 辅助记录」表；主要用在抽公共树模块、设计 d2 步骤状态机与 A/B/C 判定、设计 d3 数据生成与统计口径，以及让 AI 充当审查者做规格对照。所有 AI 产出都经测试或手动走查验证。

## 7. 不足与改进方向

- Lighthouse、FCP 与真实浏览器截图已在第 4 轮用 headless Edge + Lighthouse 补齐；Gitee Pages 已不可用，站点改由 GitHub Pages 托管并已上线；剩余的是演示视频录制，需要录屏环境，不是代码问题。
- d2 的补间动画按开题风险预案降级为「步骤切换 + CSS transition」，若时间允许可为摘下/挂接补关键帧动画。
- d3 在密集树（当前步布局半径 < 8）隐藏节点数字，保证可读，但牺牲了逐点读值；中途两树各插入前 i 个、到第 n 步才是同一批数的完整对照，页内已用文案说明。
- 屏幕阅读器只做了语义与焦点管理，未在真实读屏软件中实测；后续可补一次 VoiceOver/NVDA 走查。
- 目前用 ES5 与 IIFE 组织代码，后续可迁移到 ES Modules；但零构建带来的部署简单性也是刻意取舍。
