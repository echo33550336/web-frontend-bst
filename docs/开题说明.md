## 2. 知识点与三个难点

- **这个知识点讲的是什么（一句话）**：二叉搜索树靠“左子树全小于根、右子树全大于根”这一条局部规则，让整棵树的中序遍历天然有序；插入是顺着比较路径把新值放到它唯一的位置，删除是把节点摘掉的同时不破坏这条规则。

- **三个难点**：

| 编号 | 难点（一句话） | 学习者卡在哪一步（具体到操作） | 为什么难 |
| --- | --- | --- | --- |
| 难点 1 | 插入时比较路径为什么唯一 | 输入一个数之后，说不出“下一步该和哪个节点比、为什么只能往那边走”，也说不清“每比一次，可能的位置就少一半” | 抽象不可见：取值范围一直在收窄，这个过程在静态图上不存在，只能靠想象 |
| 难点 2 | 删除双孩子节点时，为什么用中序后继替换不会破坏有序性 | 能背出“找右子树的最小值替换”，但写到“把后继从原位置摘下来、挂到被删节点的位置”时，写不出指针该改哪几处 | 多步耦合 + 步骤太多：一次删除要动 3 处指针，漏一处就断链或自引用，而且中间状态在纸上画不出来 |
| 难点 3 | 插入顺序如何决定树的高矮 | 知道“有序插入会退化成链表”，但说不出树高、比较次数到底差多少，也分不清平均与最坏 | 反直觉：只看一棵树看不出任何异常，必须两棵树并排对比才有感觉 |

- **三个难点之间的递进关系**：难点 1 建立“位置由比较决定”这条规则 → 难点 2 说明“节点位置变了，但规则没有被破坏” → 难点 3 说明“规则一直被满足，树的形状却可以很差”。三页串起来回答同一个问题：**有序性是怎么被维护的**。

## 3. 演示策略（三个难点分别写）

### 难点 1：插入时的比较路径

- **画面构成**：中间是 SVG 树（圆形节点 + 连线），每个节点旁标出它允许的取值范围，如 `(−∞,50)`、`(50,80)`；右侧面板从上到下是：待插入值、当前比较节点、区间链（`(−∞,+∞) → (−∞,80) → (50,80)`）、剩余候选位置计数；底部是播放控件。
- **演示步骤（6 步）**：
  1. 设定待插入值 x，区间置为 `(−∞,+∞)`，高亮根节点；
  2. 比较 x 与当前节点，判定方向，高亮对应的那条边；
  3. 区间收窄，写出新区间，候选位置计数减半；
  4. 走到子节点，重复第 2—3 步，直到孩子为空；
  5. 停在空位上，显示“候选位置只剩 1 个”；
  6. 挂接新节点，跑一次全树中序校验。
- **交互类型**：参数探索型（播放控件只负责把同一过程自动演一遍，主交互是拖参数）
- **用户具体怎么操作**：拖动“插入值”滑块（1—99），树上的路径与区间链**实时重算并预览落点**；点“演示”看路径逐层亮起；随时暂停、单步、重置。
- **可调参数**：插入值 x —— 实时影响比较路径、区间链、落点位置；演示速度；树规模与“随机重生成”。
- **这个难点如何在交互中被化解**：“每层排除一半”本来是感觉，现在变成两个能读出来的量——**区间数字**和**候选位置计数**；路径高亮把“路径唯一”变成一条看得见的轨迹。

### 难点 2：删除双孩子节点

- **画面构成**：SVG 树，被删节点标红；进入选候选阶段时，三个候选节点分别标 A / B / C；指针用带箭头的连线单独绘制（区别于父子连线）；右侧状态栏显示“当前步骤 / 候选后继 / 待挂接位置”；底部是播放控件 + 删除情形切换 + 前驱/后继切换。
- **演示步骤（8 步）**：
  1. 选中目标节点，判断它属于叶子 / 单孩子 / 双孩子中的哪一种；
  2. 进入右子树；
  3. 沿左孩子一路向左走到底；
  4. 到达后继，状态栏写明“后继没有左孩子”（有左孩子它就不是最小）；
  5. 从 A/B/C 三个候选里选一个替换节点，系统判定对错；
  6. 摘下后继：改它父节点的指针；
  7. 把后继挂到被删节点的位置，接上原来的左右孩子；
  8. 校验：中序序列仍递增 + 每个节点仍落在自己的允许区间内。
- **交互类型**：步进推演型（第 5 步内嵌一次操作判定）
- **用户具体怎么操作**：先点一个节点作为目标 → 按“下一步”逐步推进 → 到第 5 步时先在 A/B/C 里选一个 → 系统给出对错与反例。可后退、可重播、可切换情形。
- **可调参数**：删除情形（叶子 / 单孩子 / 双孩子）；替换方案（前驱 / 后继）；演示速度。
- **这个难点如何在交互中被化解**：把“指针怎么改”拆成“每一步只改一处”，改完立刻能看到树的中间状态；**选错的时候当场演示断链后果**，比只看正确过程更能建立规则感。

### 难点 3：插入顺序与树退化

- **画面构成**：左右两个并排画布（同一批数据、不同插入顺序），中间参数区，下方统计面板（树高 / 平均查找步数 / 最坏查找步数）+ 一条随插入推进的折线。
- **演示步骤（5 步）**：
  1. 生成同一批 n 个数；
  2. 左树按随机顺序插入，右树按升序插入；
  3. 点“演示”，两边**同步**逐次插入（每次左右各插一个）；
  4. 每插入一个，更新三项读数并延长折线；
  5. 结束后给出对照结论：高度差多少、平均步数差多少。
- **交互类型**：对照比较型
- **用户具体怎么操作**：拖“规模”和“有序程度”两个滑块，两棵树立即重新生成；点“演示”看两边同步长高；“单步”一次一步；“重排”换一组随机顺序。
- **可调参数**：规模 n（5—60）；有序程度（从完全随机到完全升序，定义为“排序后做 k 次相邻交换”，k 可调）；演示速度。
- **这个难点如何在交互中被化解**：抽象的“平衡性”换成**可比较的形状 + 三个数字**；同一批数据、同一规模，唯一的变量只有插入顺序。

### 三者差异

- **三个难点分别用什么交互类型**：难点 1 参数探索型 / 难点 2 步进推演型 / 难点 3 对照比较型。
- **遮住标题，别人能否从操作方式分辨出这是三个不同的难点**：能。难点 1 是拖滑块驱动、结果连续变化；难点 2 是点按钮一步一停、并在关键步做选择；难点 3 是两棵树同步生长、读数跟着涨。
- **三个页面之间可以复用的部分**：导航栏、页面样式、播放控件（`common.js`）、树渲染器与 SVG 工具函数。**不可复用**的是各页的交互逻辑——`d1.js` / `d2.js` / `d3.js` 各自独立，改一页不影响另外两页。

## 6. 风险与预案

- **三个难点里我最没把握的是**：难点 2 的“摘下—挂接”指针动画——SVG 布局重算后节点要平移到新坐标，连线同时重画，很容易出现“线先到、点后到”的错位。
- **如果某个难点做不出来，降级方案是**（仍然保持三个难点，不得减为两个）：
  - 难点 2：把节点过渡动画降级为“瞬时重绘 + 前后两张快照并排对比”，指针改动仍然逐步高亮、逐步解释，交互类型不变（仍是步进推演 + 判定），只是不再做补间动画；
  - 难点 3：若 60 个节点时双画布掉帧，把规模上限降到 30，并把折线图改为“插入完成后一次绘制”，读数仍然实时更新；
  - 难点 1：若区间标注与树刷新不同步，退化为“只在当前步标出当前区间”，不做全树标注（信息量减少，但核心的收窄过程仍在）。
- **兜底**：三个难点共用一个“状态树 → 渲染”的单向数据流（一次状态、一次绘制，纯函数，无 DOM 直改），任何一页出问题都不会传染另外两页。
