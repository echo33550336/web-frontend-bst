## 3. 性能优化前后对比

本迭代没有引入构建工具或第三方运行时依赖，页面资源只有 HTML/CSS/JS/JSON。测量口径：Node v26.13.0 下直接 `require` 纯函数模块，重复运行取平均；资源体积为 `src/` + `data/` 的字节数。

| 指标 | 优化前 | 优化后 | 做了什么 |
| --- | --- | --- | --- |
| Lighthouse Performance（移动模拟） | 未测 | 首页 100 / d1 99 / d2 97 / d3 99 | 修 favicon 404、补 `<main>` 与标题层级、用占位 `viewBox` 与标题区最小高度消除布局跳动 |
| FCP / LCP | 未测 | 首页 0.9s / 0.9s；d1 1.1s；d2 1.4s；d3 1.4s | 零运行时依赖、无网络字体；只加载当前页的 3 个脚本与 1 份 JSON |
| CLS | 未测 | 首页 0；d1 0.063；d2 0.107；d3 0.05 | 标题区按最终文案预留高度、SVG 初始 `viewBox`、`.stage` 最小高度 |
| 60 节点双画布帧率 | — | 未测（纯计算：整场 60 步 1.19 ms） | 每步用 `stepState(i)` 从插入顺序重建两棵树，无累积状态；单步 0.02 ms，折线序列 60 步共 9.63 ms，预期远低于 16.7 ms 一帧 |
| 页面资源体积 | 第 9 周骨架：约 44.6 KB（src 38.7 + data 5.9） | 172.1 KB（src 156.4 KB + data 19.9 KB） | 增加三页完整交互、共用树模块、折线图与全部 JSON 文案；仍无第三方运行时库 |

| 项 | 内容 |

| AI 给出了什么（要点摘录） | ①`choose` 步未作答时拦截 `next()`，选错停在本步并渲染「可达中序 + 丢失节点清单」；②`chartSeries(caseData, index)` 只用 index 重算折线，上一步/重置天然截断；③`reshuffle` 用 salt 派生随机流，数值集合不变，100% 有序时先降到 0% 再换序 |
| 我如何验证 | 纯函数测试断言：折线点数 = index+1、后一步的前段 = 前一步整段、末点等于当前读数；页面测试断言：chart 有两条 polyline、点数随步数增长、重排后回到第 1 步且顺序改变、播放中点重排会先暂停；全套 7 个测试文件全部通过（14/28/549/154 与 28/80/131） |
| AI 版有哪些问题 | ①初版 d3 没有折线和重排，也不符合开题「画面构成 / 可调参数」；②重排若在有序程度 100% 时直接换序，会换出和升序相同的顺序，按钮看起来"没反应"；③初版漏引 `tree.js` |
| 我做了哪些修改与为什么 | ①补 chart 与 reshuffle，并写进 JSON；②重排时把有序程度降到 0%（并在 `reshuffleHint` 里解释原因），保证每次点击都有可见变化；③补脚本并加冒烟断言防回归 |
| Prompt 原文位置（commit 或附录） | 本仓库工作区会话记录；关键任务描述见 `docs/开题说明.md` 与任务板 task-2 / task-3 |
