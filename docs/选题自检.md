# 选题自检七问（第 9 周定稿前逐条过）

知识点：二叉搜索树（BST）。三个难点：① 插入时的比较路径 ② 删除双孩子节点为何用后继替换 ③ 插入顺序与树退化。

| # | 问题 | 我的回答 | 结论 |
| --- | --- | --- | --- |
| 1 | 难点有过程吗？（状态随步骤变化，而不是一句定义） | 插入有"比较 → 收窄 → 再比较"的逐步过程；删除有 8 个可停的中间状态；退化是两棵树随插入次数逐次长高 | 是 |
| 2 | 学习者卡住的位置能落到某一步具体操作上吗？ | ①卡在"输入 65 之后，下一步该和谁比"；②卡在"把后继摘下来、挂上去"的指针改动；③卡在"换个顺序，树高差多少"这个数字上 | 是 |
| 3 | 如果不画图、只靠文字，讲得清吗？ | **结论讲得清，过程讲不清**——文字能写"用中序后继替换"，但写不出"区间从 (50,∞) 收窄到 (50,70)"和"三处指针分别指到哪"。要可视化的正是过程，不是结论 | 是（且恰好说明可视化是必需的） |
| 4 | 我设计的交互是在帮助理解，还是只是让页面动起来？ | 每条交互都对着一个具体误解：区间数字对"路径为什么唯一"、A/B/C 判定对"为什么不能随便换个节点"、并排读数对"退化到底差多少" | 是 |
| 5 | 这个知识点能找到 3 个需要交互辅助理解的难点吗？ | 能，且三条共享同一条主线（有序性如何被维护），不是三个不相干的知识点拼盘 | 是 |
| 6 | 3 个难点的交互理解方式有差异吗？ | 有：参数探索（拖滑块看收窄）/ 步进推演 + 判定（点按钮推进、关键步做选择）/ 对照比较（双画布同步生长） | 是 |
| 7 | 一个人、8 周、3 个交互页面，做得完吗？ | 做得完，前提是节奏：第 10—12 周只保一个难点完整（难点 1 最简单，先打通外壳），难点 2 最难放在第 13—14 周，难点 3 复用同一套渲染器 | 是 |

## 一个补充判断：不是"排序算法可视化"

"排序算法可视化"这个问题在第 5 问上会失分——三个算法各讲一点，谁也不深。本选题的三个难点都在一棵树上，
讲的是同一条规则（左小右大）在三种操作下的表现，属于"一个知识点的三个侧面"，符合要求。

## 与课程示例的关系（自查，别撞车）

课程《课程项目要求 v2》第五节给的完整示例也是 BST，但它把三个难点映射成「插入＝步进推演 / 删除＝操作判定 / 退化＝参数探索」。
本选题的重心不同：

- 插入做成**参数探索**（拖滑块实时看区间收窄与落点），而不是一步一停；
- 删除做成**步进推演**（8 步逐步改指针），判定只作为第 5 步的一个内嵌环节；
- 退化做成**对照比较**（双画布同步插入 + 三个读数），而不是只调参数看一条曲线。

三种交互都能对上要求里的五种类型，但每一页"用户做什么"和示例不同——遮住标题能分辨出来。
